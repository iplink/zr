# Залив-Ретрит · ZALIV-RETREAT.RU

Сайт загородного отеля с отдельными страницами трёх домов и ботами для приёма заявок. Два варианта размещения: **PHP 8.3 для обычного хостинга REG.RU** или Node.js 22+ для сервера. База данных не требуется.

## REG.RU: PHP 8.3 / FastCGI (Apache)

Бот MAX также подключается к этому проекту: [инструкция MAX](hosting/MAX.md). Используется тот же сценарий бронирования и общая очередь уведомлений. Токен, ID администратора и ключи webhook исключены из Git.

Для подтверждённой владельцем версии PHP 8.3.37 подготовлены обработчик формы, бот через защищённый webhook, локальная очередь и задание планировщика для доставки. Подробная инструкция: [hosting/REG-RU.md](hosting/REG-RU.md). Собрать пакет без секретов: `node scripts/build-hosting.mjs`. Локальная сборка с настройками владельца: `node scripts/build-hosting.mjs --private`; результат и секреты исключены из Git.

PHP-код проверяется командой `php hosting/php/tests/run.php`. Бот через webhook отвечает без постоянно работающего процесса; для доставки уведомлений требуется задание Cron, описанное в инструкции. Далее в этом README описан альтернативный запуск на Node.js.

Фото и описание карточек на главной ведут на эти страницы; кнопки переключения галереи и выбора дома сохраняют своё действие.

## Запуск

Характеристики и цены домов находятся в `content/houses.json` и уточнены владельцем 21 ноября 2026 года. Для обновления локальных HTML-страниц выполните `node scripts/build-house-pages.mjs`. Сборка хостинга автоматически пересоздаёт их и проверяет заполненность обязательных сведений. Число спальных мест не изменяет лимит гостей: Белый дом — 10 мест / 8 гостей, Уединённый — 6 / 4, дом с баней — 4 / 4. Вместимость парной — 6 человек; это отдельная характеристика. Начальные цены за сутки: 19000 / 9900 / 15900 рублей соответственно. Для дома с баней растопка бани включена, растопка чана оплачивается отдельно по желанию.

```sh
pnpm install --frozen-lockfile
cp .env.example .env
pnpm start
```

Локальный адрес: `http://localhost:3000`. Для локальных заявок задайте `SITE_URL=http://localhost:3000`. Без настроенной почты и Telegram сервер честно отвечает о недоступности отправки; успешная отправка не имитируется.

Можно использовать npm: `npm install`, `npm start`, `npm test`.

## Подключение почты

Заполните `.env` на сервере:

```dotenv
EMAIL_TO=vi-kate@mail.ru
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=iplink@mail.ru
SMTP_FROM=iplink@mail.ru
SMTP_PASS=пароль_внешнего_приложения
```

Указанные параметры подготовлены для отправителя Mail.ru. Пароль приложения получите в настройках используемого ящика; доступность SMTP проверьте у провайдера. Обычный пароль от почты не требуется. `SMTP_FROM` должен быть разрешённым адресом отправителя. Для другого провайдера измените хост, порт и пользователя.

## Подключение Telegram

Бот проекта: **@ZalivBookingBot** — https://t.me/ZalivBookingBot. Ссылки на него уже размещены на сайте. Имя получено от владельца; токен хранится только в локальном `.env`. Для доставки уведомлений требуется числовой `TELEGRAM_ADMIN_CHAT_ID` администратора. Имя бота не заменяет этот ID. Перед получением уведомлений администратор должен открыть бота и нажать «Старт».

1. Откройте **@BotFather** в Telegram, отправьте `/newbot`, выберите имя и свободный username. Если бот уже создан, используйте его токен.
2. Сохраните токен в `TELEGRAM_BOT_TOKEN` в `.env`. Этот файл исключён из Git.
3. Установите `BOT_ENABLED=true` и запустите сервер.
4. Откройте своего бота, нажмите «Старт», отправьте `/id`. Ответ будет содержать ваш личный `chat_id`.
5. Запишите его в `TELEGRAM_ADMIN_CHAT_ID` и перезапустите сервер.
6. При заполненных SMTP-параметрах отправьте `/book`, пройдите сценарий и проверьте оба уведомления.

Для админских уведомлений используйте личный чат с ботом. Диалоги бронирования работают только в личных чатах. Не запускайте два экземпляра одного бота одновременно. Реализован long polling; webhook у бота должен быть отключён. Скрипт автоматически не меняет существующий webhook. Для проверки только страницы можно временно задать `BOT_ENABLED=false`.

Сценарий: дом → заезд → выезд → гости → имя → телефон → согласие → приём основной заявки → вопрос о пожеланиях. Даты вводятся и показываются в формате **ДД.ММ.ГГГГ**; проверка и хранение используют ISO. После приёма основной заявки бот предлагает написать пожелания одним сообщением или отправить `/skip`. Пожелания доставляются на почту и в Telegram отдельным дополнением с номером исходной заявки. `/cancel` на этом этапе пропускает только пожелания и не отменяет уже принятую заявку. Подтверждение бронирования администратором обязательно.

## Публикация

Нужен сервер с Node.js, постоянным диском и исходящим доступом к SMTP и `api.telegram.org`. Один процесс, автоматически перезапускаемый менеджером процессов. Статический GitHub Pages для отправки заявок и работы бота недостаточен.

1. Установите зависимости и заполните `.env` на сервере, `SITE_URL=https://zaliv-retreat.ru`.
2. Направьте DNS-записи домена на IP сервера и настройте HTTPS.
3. Используйте пример `deploy/nginx.conf` для перенаправления запросов к `127.0.0.1:3000`. HTTPS-сертификат и пути к нему задаются на вашем сервере.
4. Включите `TRUST_PROXY=true` только за доверенным прокси, который перезаписывает `X-Forwarded-For`.
5. Сохраните каталог `data` на постоянном диске с доступом только владельцу процесса. Он содержит ещё не доставленные заявки; не публикуйте его и `.env`.
6. Проверьте `/health`, отправку с сайта, уведомления на почту и в чат, затем `/book` в Telegram.

Очередь повторяет доставку до успеха, максимальный интервал — час. Контролируйте сообщения `Delivery failed` и остатки `data/*.json`. Если внешний сервис принял уведомление, но соединение оборвалось до подтверждения, возможен повтор; номер заявки помогает распознать дубликат. Локальная очередь защищает от обычных перезапусков, но не от потери диска; предусмотрите эксплуатационные резервные копии и правила хранения данных.
