# Размещение на REG.RU · PHP 8.3

Подключение существующего бота MAX описано в [MAX.md](MAX.md). Новая сборка включает его обработчик и официальный набор сертификатов. Для доставки в MAX используется то же задание планировщика; значения токена и чата берутся из закрытого файла настроек.

Версия для обычного хостинга с PHP 8.3, FastCGI (Apache), расширениями cURL, OpenSSL и ctype. Она использует тот же дизайн сайта. Node.js, отдельный VPS и база данных для этой версии не нужны.

## 1. Создайте сайт

В панели нажмите **«Создать сайт»**. Укажите домен **zaliv-retreat.ru** и оставьте выбранную версию **PHP 8.3 / FastCGI (Apache)**. Запишите путь корневой папки сайта. Обычно он заканчивается на `/www/zaliv-retreat.ru`, но используйте именно путь из своей панели.

Домен должен быть зарегистрирован и направлен на этот хостинг. Точные DNS-серверы или IP возьмите из параметров вашей услуги REG.RU: в проекте они не выдуманы. Включите действительный HTTPS-сертификат для домена. Затем включите перенаправление HTTP → HTTPS средствами панели.

## 2. Загрузите файлы

Архив содержит две папки, которые должны оказаться **рядом**, а не внутри друг друга:

```text
www/
├── zaliv-retreat.ru/        ← корневая папка сайта из панели
│   ├── index.html
│   ├── app.js
│   ├── style.css
│   ├── .htaccess
│   ├── images/
│   └── api/
│       ├── booking.php
│       ├── telegram.php
│       └── connect.php
└── zaliv-private/           ← соседняя папка ВНЕ корня сайта
    ├── config.php
    ├── app.php
    ├── bot.php
    ├── cron.php
    ├── vendor/
    └── data/               ← создаётся автоматически
```

Через файловый менеджер поднимитесь на один уровень выше папки сайта, загрузите архив и распакуйте его там. Убедитесь, что файлы из `zaliv-retreat.ru` попали именно в корень сайта, без лишней вложенности. Если в корне уже есть стартовая страница хостинга, сохраните её копию и замените `index.html` нашей страницей.

**Готовый локальный архив `zaliv-retreat-reg-ru-ready.zip` содержит рабочие секреты в `zaliv-private/config.php`.** Не помещайте его в папку, доступную через сайт, не коммитьте в GitHub и не отправляйте третьим лицам. После распаковки удалите загруженный ZIP из файлового менеджера. Папку `zaliv-private` нельзя переносить внутрь `zaliv-retreat.ru`.

В GitHub лежат только исходники и пример конфигурации. Публичная сборка без секретов требует заполнить `zaliv-private/config.php` по `config.example.php` на хостинге. Файл конфигурации должен читаться процессом PHP, но не посторонними пользователями. Директория `zaliv-private/data` должна быть доступна PHP для записи. Не используйте права 777.

## 3. Добавьте задание планировщика

Откройте **«Планировщик» / Cron**. Добавьте запуск каждую минуту:

```sh
/путь/к/php /полный/путь/www/zaliv-private/cron.php
```

Оба пути возьмите из панели или уточните в поддержке REG.RU для PHP 8.3. Не подставляйте пример буквально. Если в планировщике можно выбрать версию PHP и файл, выберите **8.3** и `zaliv-private/cron.php`.

Это задание доставляет заявки из бота и повторяет неудачные отправки с сайта. **Без планировщика доставка заявок из Telegram не заработает**, даже если диалог бота отвечает. Серверные задания работают только через командную строку; открытие `cron.php` браузером заблокировано.

## 4. Подключите бота

Сначала проверьте, что `https://zaliv-retreat.ru/` открывает наш сайт без предупреждений о сертификате. Остановите Node.js-версию этого бота, если она запущена: polling и webhook одного бота не должны работать одновременно.

На локальном компьютере из папки проекта выполните:

```sh
node scripts/connect-hosting.mjs
```

Скрипт использует локальный закрытый ключ из `hosting/.secrets.json` и вызывает защищённый `api/connect.php` на вашем домене. Хостинг проверит токен и чат администратора, зарегистрирует команды и webhook. Адрес webhook: `https://zaliv-retreat.ru/api/telegram.php`. Секрет передаётся Telegram в заголовке, а не в адресе.

Бот: **@ZalivBookingBot**. Для личных уведомлений администратор должен хотя бы один раз нажать «Старт» в этом боте. Само нажатие «Старт» не запускает серверный код.

Формат дат на сайте, в боте и в уведомлениях: **ДД.ММ.ГГГГ**. После приёма основной заявки бот спрашивает пожелания; ответ отправляется отдельным дополнением с номером исходной заявки. Команда `/skip` пропускает пожелания. На этом этапе `/cancel` также пропускает только пожелания, не отменяя принятую заявку.

Если использована ручная конфигурация вместо готового локального архива, значения `setup_secret` и `webhook_secret` должны совпадать с локальным `hosting/.secrets.json`. Регистрировать webhook нужно после каждого изменения домена или этих секретов. Не публикуйте секреты и не добавляйте их в URL. После успешного подключения можно убрать публичный файл `api/connect.php`; бот и заявки продолжат работать.

## 5. Проверьте доставку

Отправьте с сайта одну контрольную заявку, затем пройдите `/book` в боте. В пределах интервала планировщика должны прийти уведомления на **vi-kate@mail.ru** и в чат администратора. Отправитель почты — **iplink@mail.ru**. Запишите номер заявки, если потребуется найти повтор.

Если уведомления задерживаются, проверьте:

- Запуск планировщика и его журнал; доступность PHP 8.3 в CLI.
- Доступ PHP к cURL/OpenSSL и исходящим соединениям с `smtp.mail.ru:465` и `api.telegram.org:443`.
- Права записи в закрытую папку данных и ошибки `Zaliv delivery failed` в журнале PHP.
- HTTPS и корректность DNS домена.

Форма подтверждает приём заявки только после сохранения на диск. Это не подтверждение свободных дат или оплаты. После доставки по обоим каналам запись очереди удаляется. Повторная отправка канала, уже отмеченного доставленным, пропускается. При обрыве соединения после фактической доставки возможен дубликат; номер заявки позволяет его узнать.

## Сборка из исходников

```sh
node scripts/build-hosting.mjs
node scripts/build-hosting.mjs --private
```

Первая команда создаёт `dist/reg-ru-public` без секретов. Вторая читает локальный `.env`, создаёт/использует `hosting/.secrets.json` и готовит `dist/reg-ru-ready` с закрытой конфигурацией. Эти каталоги исключены из Git. Упакуйте содержимое нужного каталога ZIP-архивом вместе с `.htaccess`.

Библиотека PHPMailer 7.2.0 включена из официального репозитория, три исходных файла и лицензия LGPL: https://github.com/PHPMailer/PHPMailer/tree/v7.2.0. Внешних загрузок библиотек на хостинге не требуется.

Исходные фотографии и тексты объявлений Авито по-прежнему требуют добавления владельцем: текущая версия сохраняет явные подписи к иллюстрациям домов. Подготовка PHP-версии сама по себе не означает, что сайт уже загружен на хостинг.
