# Бронирование в MAX

Подключён существующий бот **«Залив-Ретрит-Бот»**, username `se15088019_bot`. Токен и чат администратора хранятся только в локальном `.env` и закрытой конфигурации на хостинге.

## Локальный режим

В `.env`:

```dotenv
MAX_BOT_TOKEN=токен_существующего_бота
MAX_ADMIN_CHAT_ID=номер_личного_диалога
MAX_ENABLED=true
MAX_CA_FILE=hosting/php/private/certs/max-ca.pem
```

После `pnpm start` сервер подключается к официальному `platform-api2.max.ru` и запускает получение событий. Если уже есть webhook, локальный polling пропускается, чтобы не перехватывать рабочий поток сообщений. Одновременно запускайте только один локальный экземпляр.

Сценарий общий с Telegram: `/book` → дом → даты **ДД.ММ.ГГГГ** → гости → имя → телефон → согласие → сохранение основной заявки → необязательные пожелания или `/skip`. Пожелания отправляются дополнением с номером исходной заявки. Отмена пожеланий не отменяет основную заявку.

При заполненных `MAX_BOT_TOKEN` и `MAX_ADMIN_CHAT_ID` новые заявки с сайта и обоих ботов доставляются на почту, в Telegram и в MAX. Очередь запоминает состав каналов и чат MAX на момент приёма заявки. Сбой одного канала не повторяет уже подтверждённые отправки по остальным каналам.

Для безопасной первичной привязки чата локальная версия поддерживает одноразовую команду `/connect <код>` с ограниченным сроком действия. Код не публикуется в меню. После успешной привязки удаляется из настроек. Чат другого человека не выбирается автоматически по первому входящему сообщению.

## REG.RU / PHP 8.3

Сборка `node scripts/build-hosting.mjs --private` включает параметры MAX из `.env` в закрытый файл `zaliv-private/config.php`. Обновлённый архив содержит сертификаты, обработчик `api/max.php` и защищённый установщик `api/connect-max.php`.

1. Загрузите новую сборку по [основной инструкции](REG-RU.md), сохраняя `zaliv-private` вне корня сайта.
2. Проверьте HTTPS домена и работу существующего задания `zaliv-private/cron.php` каждую минуту: оно доставляет уведомления из обоих мессенджеров.
3. Остановите локального MAX-бота перед переключением на webhook.
4. Выполните локально `node scripts/connect-hosting.mjs --max`.
5. Защищённый установщик проверит личность бота, настроит команды через `PATCH /me/commands` и подпишет `https://zaliv-retreat.ru/api/max.php` на `message_created` и `bot_started`.

Webhook проверяет заголовок `X-Max-Bot-Api-Secret`; его значение генерируется локально и не входит в Git. Состояния диалога, квитанции обработки событий и очередь хранятся в закрытой папке. Повтор события не создаёт вторую заявку и не сдвигает шаг диалога. Если отправка ответа клиенту не удалась, повтор того же события повторяет только доставку ответа. Работа с гостями ведётся в личных диалогах, сообщения групп и других ботов игнорируются.

## Сертификаты

Файлы в `php/private/certs` загружены с официального ресурса портала Госуслуг:

- `https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt`
- `https://gu-st.ru/content/lending/russian_trusted_sub_ca_pem.crt`

`max-ca.pem` содержит эти два сертификата. Публичные сертификаты не содержат токенов или паролей. Проверка подлинности сервера и имени `platform-api2.max.ru` включена; набор CA применяется только к MAX. Общесистемное хранилище сертификатов не меняется.

На момент проверки корневой сертификат действует до 27.02.2032, промежуточный — до 06.03.2027. Обновляйте набор сертификатов из официального источника до истечения срока и проверяйте новую цепочку.

Документация: https://dev.max.ru/docs-api, https://dev.max.ru/docs-api/methods/PATCH/me/commands/.
